# Apollo Connected 26.1 — CRM database import/export

Built from the uploaded `(26.1)ApolloFreightERP-main (26).zip`.

Open CRM > Accounts > Database import / export.

Import: select XLSX, XLS or CSV (5 MB, 5,000 rows per worksheet). Choose header row and read columns. For another worksheet, choose it and click Read columns again. Map company (required), contact name, email, phone, mobile, job title, website, country, city, address and notes. Select an active salesperson and DXB or KWI. Preview before confirming. Process each worksheet separately.

No deals, opportunities, activities or pipeline history are imported. Only mapped fields are read; unmapped source columns are ignored. Preserve phone numbers as text in the source workbook, especially leading zeros. Company is required for each contact row.

Existing companies match on normalized company name + exact entity label. Existing company details and ownership are preserved; new contacts can be added. Existing archived/ambiguous matches stop the batch. Identical name/email/phone/mobile combinations within a company are skipped. Different spellings or different entity labels (e.g. Dubai versus DXB) require review: they do not automatically merge. All imported companies use Prospect status. Source Salesforce/Pipedrive IDs are not imported.

Bulk assignment: load accounts, search/filter, select records or select all filtered, choose salesperson and/or entity and apply. Blank means leave that field unchanged. Existing open work assigned to the previous account owner follows the new owner; visit authors/history remain unchanged. Intentional delegation to other users is preserved. Owner/entity edits are audited.

Export: download an XLSX containing companies with contact details, entity and salesperson. Access is enforced by existing export and account visibility permissions. Formula-like content is exported as text cells. Import does not automatically restore owner/entity columns from an export: select those settings deliberately.

IT: deploy the full project using the existing process. No dependency or schema changes. Existing CRM tables from migration 037 must already exist. Keep current environment/secrets. Do not run all migrations solely for this update. Existing HR, shipment email, AI and task email code is preserved.

Changed files: server/src/crm.js (register database routes), server/src/crm-database.js (new), web/crm-portal.js, web/app.js, web/index.html; this README is new.

Verification: Node syntax checks; XLS/XLSX/CSV parsing with text phone numbers; actual PostgreSQL SQL via local PGlite using migration 037; preview rollback, import commit, duplicate reimport, invalid owner, selected-account reassignment, XLSX export, restricted export scope and unauthorized import/export. Tests used synthetic customer data. Actual Pipedrive/Kuwait spreadsheets were not provided. No live deployment or visual browser test was performed.

Before production import: back up the database; import a small representative sample, confirm contacts/ownership/entity, then load the remaining data. Newly imported batches do not have an automatic undo button. Preview allocates sequence numbers which can leave harmless gaps after rollback.
