# Apollo Connected V24.1 — HR review hotfix

This is the complete V24 project with a narrowly scoped HR hotfix. Deploy BOTH the server and web files. Keep your current live database, environment variables and Microsoft Graph / Secret Manager configuration. Do not replace them with test data. No new database migration is introduced by V24.1.

## Why this update

V24 sent management notifications independently of the logged-in user's approval permissions. A legacy administrator with HR access disabled or missing final-approver settings could receive the email but be denied the review. The review UI also required an Employee Portal session even when an authorised manager used ERP login, and offered a supervisor recommendation to a management-only reviewer. These paths are corrected. The precise live account/request configuration was not accessible during development; the screenshot alone cannot prove which path caused that particular failure.

## Deploy

1. Retain the deployed V24 build and take your normal database backup/snapshot.
2. Build/deploy this complete project using your existing V24 process. Deploy the web directory as well as the server. Dependencies, Dockerfile, schema migrations and mail settings are unchanged.
3. If web and API are separate deployments, retain the correct live APOLLO_API_URL in web/config.js. Existing email links must lead to that same deployment/database. Do not deploy only the new frontend against an old backend.
4. Purge any hosting/CDN cache for hr-approvals, hr-approvals.html, hr-approvals.js, hr-approvals.css, hr-workflow-links.js, app.js and app-runtime.js. The review page has absolute versioned asset URLs, bundled fallback styles and a visible “Connected HR · V24.1” footer. Standard Express/Vercel HR responses are marked no-store.
5. Reopen the original request email link and reload. Sign in with Khaldoun's own Connected administrator account (ERP or Employee/HR), not a shared noreply mailbox login.
6. If shown, click **Enable management approvals for my account**, read the confirmation, then confirm. This explicitly sets HR access, Management Final Approver and Management Override for the currently logged-in active administrator only. It records an audit event and returns to the same request. No ordinary employee, CRM session, inactive account or email recipient can self-enable. Already configured managers go directly to the request.
7. If the account email is missing/invalid, correct it in User Management before setup. If setup is not wanted, an HR-enabled administrator can continue with existing permissions without granting themselves management approval.

An existing V24 database must already have migrations 047 and 048. If the page explicitly reports a missing HR database update, run the existing V24 HR migration procedure in V24-IT-SETUP.md against the correct database. Never reset, reseed or delete the database to resolve this.

## Assign supervisors in the SAME user settings window

1. In User Management, edit the supervisor: Active account, valid email, HR Portal access enabled, one specific Branch Access, and **Leave Approver — own branch, assigned employees only** checked. Save once.
2. Edit or create the employee, set the employee's Branch Access, then select **Assigned supervisor** in the Leave approval permissions section of this same form. Only eligible same-branch supervisors are offered. Save once; user details and leave permissions are one transaction. No second settings tab is required.
3. Leave Management Final Approver and Management Override unchecked for ordinary supervisors/employees. Give those to the intended management account only.
4. A supervisor assignment change applies to new/resubmitted requests. For an EXISTING pending request, management must open it and use **Forward / reassign supervisor** with a comment. This preserves its decision history instead of silently rerouting it.

## Approval behavior

- Employee submission notifies supervisor and management; receiving email alone grants no access.
- Assigned same-branch supervisor can recommend approval, deny, return with comments, or forward to another eligible same-branch reviewer.
- Normal supervisor approval leaves the request pending for final management approval.
- Management can explicitly use **Management override — approve now** before supervisor review or after denial, with a mandatory explanation. This is audited and deducts leave only once. Ordinary final approval remains available after supervisor review.
- Self-approval is blocked. Leave balance, required-document checks, stale-decision protection and forwarding controls remain intact.
- Clicking an email link only opens the review. It never makes a decision automatically.
